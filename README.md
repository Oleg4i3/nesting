# Нейромережевий оператор відновлення в LNS для розкрою деталей довільної форми на заготовках з дефектами

Код, ваги, дані експериментів і веб-симулятор до статті про компактну нейромережу (449 параметрів, чистий JavaScript, без GPU) у ролі оператора відновлення в пошуку у великому околі (LNS) для нерегулярного розкрою на рулонах з дірками й нерівними краями.

Ідея: у низькотемпературній фазі LNS видаляє 3–8 сусідніх деталей, а мережа обирає, куди повернути кожну з них, замість нижнього лівого методу (BL). Мережу навчено з учителем на станах відновлення, зібраних з розкладок LNS на лекалах (softmax по кандидатах: 1 позитив і до 150 негативів). Порівняння: Sparrow v0.3.0 із нашим патчем про зони заборони, одноетапний LNS + BL і контроль (той самий двоетапний LNS без мережі).

> Статус: дослідницький код. Вибірки малі (64 задачі з 8 наборів лекал), дефекти згенеровано випадково, растрові щільності наших методів не скориговано на перетин деталей (див. «Обмеження»).

## Головні результати

Задачі: 8 наборів лекал (костюм, блуза й сукня, п'ять наборів FreeSewing), 2–3 вироби, кути {0°, 90°, 180°, 270°} або крок 5°, рулони «край і дірки» та «лише дірки», зерно 201 (не брало участі в підборі параметрів і навчанні), 10 с на задачу на одному потоці, Sparrow по 3 запуски. Парний знако-перестановочний тест за задачами, bootstrap 95% ДІ, Holm за чотирма сценаріями.

| | різниця, п.п. | 95% ДІ | p |
|---|---|---|---|
| LNS + мережа − контроль (усі 64) | +0,93 | 0,59–1,32 | < 0,001 |
| LNS + мережа − Sparrow (усі 64) | +3,13 | 2,28–4,00 | < 0,001 |
| те саме, крок 5°, край і дірки (16) | +7,33 | 6,02–8,50 | < 0,001 |
| те саме, кути 90°, лише дірки (16) | −0,14 | −0,85…+0,53 | 0,70 |

Більшу частину виграшу над Sparrow дає сам LNS (+2,26 п.п.), мережа додає менше одного пункту.

Тест із десятикратним бюджетом (100 с, 8 задач сценарію «крок 5°, край і дірки»): виграш над Sparrow зменшується з +6,3 до +1,7 п.п. (p = 0,016; проти найкращого з трьох запусків +1,2, p = 0,047); див. `docs/test_10x_chas.md`. Мережа як самостійний розв'язувач і гібрид «мережа → LNS» на реальних лекалах виявилися невдалими; додавання пазлів до даних відновлення ефекту не дало.

## Відтворення

Потрібен Node.js 18+, для статистики Python 3 (numpy). Sparrow збирається окремо (див. нижче).

```bash
# 1. дані відновлення (дві частини) і навчання мережі
#    аргументи: <ч> <частин> <тег> <задач з лекал> <задач-пазлів> <мс LNS> <кластерів на задачу>
node repair_data2.js 0 2 rep2tm 160 0 8000 20 &  node repair_data2.js 1 2 rep2tm 160 0 8000 20 ; wait
#    у статті використано підмножину даних з kind = tm_* (задачі з лекалами; пазли виключено)
node train_v3.js rep2tm_16_8 rep2tm rep2tm 60 1 16,8 0   # <ім'я> <теги> <валід.тег> <епох> <зерно> <шари> <CUR>; найкраща контрольна точка (у статті — епоха 52)

# 2. оцінювання на зерні 201: ctrl / all / tm, 10 с, 2 процеси
node mg2_ablate.js 0 2 abl weights/v2/rep2_16_8_b.json weights/v2/rep2tm_16_8.json 10000 suit,fs_jaeger,fs_charlie,fs_wahid,fs_korf_blouse,fs_korf_dress,fs_simon,fs_hugo 2,3 any,deg5 both,pholes 201

# 3. Sparrow із патчем про зони (3 зерна, 10 с, 1 потік) і перевірка точною геометрією
node ext/mg_sparrow_export.js ; bash ext/mg2_sparrow.sh     # -> ext/zscen/dens.json

# 4. статистика й рисунки
python3 mg3_stats.py                         # -> results/mg3_stats.json/.txt
node figures/make_svgs4.js                   # fig16_mg3.svg, fig17_mg3_paired.svg

# 5. десятикратний бюджет (100 с) на 8 задачах
bash ext/run_long.sh
```

Шляхи до зібраного Sparrow у `ext/*.sh` налаштуйте під себе (за замовчуванням `/home/claude/ext/sparrow_def`).

## Браузерний симулятор

Увесь рушій і ваги вбудовано в один HTML. Розрахунок іде у Web Worker, по одному методу за раз, тому виміряний час чесний (одне ядро). Для кожної задачі видно розкладку, щільність, довжину розкрою й час кожного методу, а повзунок показує порядок укладання.

Над результатами є панель параметрів сцени: ширина рулона (поле й швидкі множники ×0,8 … ×2 від початкової), набір поворотів (без поворотів, 0°/180°, кратні 90°, 15°, 5°, «як у файлі»), дзеркала й попередження, якщо деталь не вміщується. Друга панель задає зони рулона: нерівний край (ліворуч, праворуч, з обох боків), дефекти-дірки (0–8), обрізані кути (0–2) і зерно; генератор той самий, що в `zones.js`/`rl_tasks.js`. Згорнутий блок «Редактор деталей» — це редактор контурів із Без'є (деталі можна перетворити на нову задачу або додати до поточної); кнопка збереження у файл у вбудованому вікні не працює, експортуйте через «Копіювати результат». Перша в списку прикладів — набір викрійок костюма, якщо збірку зроблено з приватним файлом.

Підтримувані формати JSON:

1. `nest-scene-v1`, власний формат (приклади в `examples/scenes/`);
2. набори ESICUP/Sparrow (`items`, `strip_height`): деталі масштабуються до висоти смуги 300 px, повторення за `demand` розгортаються, підтримується лише `simple_polygon`;
3. JSON редактора розкрою (`polygons` з `vertices` і `bezierControls`).

Формат `nest-scene-v1`:

```json
{
  "format": "nest-scene-v1",
  "name": "my_task", "title": "Моя задача",
  "width": 300,
  "rotations": [0, 90, 180, 270],
  "mirror": false,
  "pieces":  [{"v": [[0,0],[100,0],[100,60],[0,60]], "c": [null,null,null,null]}],
  "blocked": [],
  "reference": {"name": "Еталон", "length": 400, "polys": []}
}
```

`c[i]` — контрольна точка кривої Без'є для ребра `i → i+1` (або `null` для прямого ребра). `blocked` — заборонені зони. `reference` необов'язкове: готовий розв'язок для порівняння.

## Методи (ключі в симуляторі та скриптах)

| Ключ | Метод |
|---|---|
| lns | одноетапний LNS: руйнуємо k = 6–14 сусідніх деталей, відновлюємо BL, приймаємо за SA |
| ctrl | двоетапний LNS: перша половина бюджету — lns; друга — LNS при T0 = 0,05, T1 = 0,01, k = 3–8 від найкращої розкладки, відновлення лише BL |
| net / tm | те саме, але видалену деталь повертає мережа з імовірністю 0,5 (softmax, температура 0,3), інакше BL |
| bl, net-only, hyb | BL-відпал; мережа як самостійний розв'язувач; гібрид «мережа → LNS» (невдалі спроби, лишено для відтворюваності) |

## Зовнішні розв'язувачі

Порівняння проводилося з Sparrow (Rust, `github.com/JeroenGar/sparrow`, комміт `6f7b9d3`) і SVGnest (`github.com/Jack000/SVGnest`, комміт `1248dc2`). Їхній код у репозиторій не входить.


Протокол: 30 с на задачу, один потік/ядро, один запуск, `strip_height` = ширина рулона; щільність = Σ площ / (ширина × використана довжина).

## Обмеження

Одне зерно рулонів на комбінацію «набір × сценарій»; 64 задачі з 8 залежних наборів лекал; дефекти згенеровано випадково; форми дірок узято з пулу викройок FreeSewing; растр з кроком 10 px і вручну задані ознаки; бюджет 10 с на одному ядрі (тест на 100 с — лише 8 задач). Sparrow не призначений для заготовок з дефектами: зони додано нашим патчем, параметри не налаштовували. Щільності наших методів лічено на растрі й не скориговано на перетин деталей (0,2–2 % площі в раніших перевірках), тоді як розкладки Sparrow перевірено точною геометрією (shapely). Час роботи не є предметом дослідження.

Бюджет 30 с на одному ядрі. Щільність, %. Для нашого рушія деталі масштабовано до висоти смуги 300 px, довжина розкрою кратна 5 px (близько 1,7 % ширини смуги).

|---|---|---|---|---|---|---|---|---|---|
| marques | 24 | 84.9 | 86.8 | 88.7 | 88.7 | 0.9 | 87.8 | 88.5 | -0.8 |
| albano | 24 | 77.2 | 85.3 | 86.0 | 86.0 | 0.3 | 85.7 | 88.0 | -2.3 |
| dagli | 30 | 77.8 | 81.6 | 84.3 | 82.9 | 0.2 | 84.1 | 84.9 | -0.8 |
| mao | 20 | 75.4 | 80.7 | 82.6 | 82.6 | 0.7 | 81.9 | 81.8 | +0.1 |
| swim | 48 | 65.9 | 68.9 | 72.1 | 73.2 | 0.8 | 72.4 | 73.2 | -0.8 |
| trousers | 64 | 75.9 | 82.7 | 78.0 | 77.3 | 0.3 | 77.7 | 89.5 | -11.8 |
| shirts | 99 | 81.0 | 85.3 | 87.1 | 87.1 | 1.4 | 85.7 | 85.5 | +0.2 |


Растровий рушій перевіряє перетин за центрами клітинок, тому на реальних контурах деталі можуть трохи заходити одна на одну. Ми виміряли це точно (shapely, `ext/overlap_check.py`, розкладки LNS за 8 с): від 0,2 до 1,4 % площі деталей. Колонка «Найкращий наш з поправкою» — це щільність кращого з LNS і гібрида мінус виміряний перетин. Sparrow дає розкладку без перетинів. Різниця з Sparrow після поправки лежить у межах ±1 п.п. на п'яти наборах із семи (marques, dagli, mao, swim, shirts), на albano −2,3 п.п., на trousers −11,8 п.п. Чиста мережа (з комбінованим відбором: кілька критеріїв ранжування променів, `portfolio.js`) поступається BL-відпалу на 1,9–8,1 п.п. на всіх семи наборах.

Висновок: на реальних лекалах гібрид і LNS у нашому рушії порівнянні зі Sparrow на малих і середніх наборах, але не перевершують його, а на trousers істотно програють. Один запуск на набір, тож різницю в 1–2 п.п. не можна відрізнити від випадкової.

### Додаткові експерименти (донавчання, рулони, кут, ширина)

```bash
# донавчання з підкріпленням на реальних деталях (сценарії рулона: plain/defects/ragged/both)
node rl_train.js <ім'я> <стартові ваги> <real|scen|free|freescen> [ітерацій=80] [пар=14] [задач на батч=24] [sigma=0.04]
# перевірка на відкладених задачах (набори, яких мережа не бачила): частина, частин, тег, rot, види рулона, зерна, моделі ім'я=шлях
node rl_eval.js 0 1 test dataset plain,defects,ragged,both 1,2 base=weights/v2/r3a.json,rl=weights/v2/rl_scen2.json 10000 marques,mao,shirts
# ширина рулона: набір ESICUP або suit (приватний), множник ширини, зерно, бюджет мс

# кілька зерен для стохастичних методів
SEED=2 METHODS=bl,lns,hyb node ext_real.js ours 30000
SEED=2 METHODS=bl,lns,hyb node ext_export.js ours 30000
# боксплоти зі статті
python3 figures/build_data2.py && python3 figures/build_data3.py && python3 figures/build_data4.py && python3 figures/build_data5.py && node figures/make_svgs2.js
# build_data5.py лишає в рисунках 4–5 найпоказовіших рядків; Sparrow і SVGnest — по 3 запуски (ext/sp/*_s{2,3}.log, ext/sp_real/*_s{2,3}.log, ext/svg_fix/run{1,2,3} (SVGnest із виправленим входом: деталі не накладаються, інакше він мовчки пропускає деталі всередині контурів інших; запуски з неповним набором відкидаються))
```

Головні висновки цих експериментів (докладно в статті): донавчання з підкріпленням дає невеликий приріст мережі (близько +2 п.п. на задачах, яких вона не бачила), але BL-відпал і LNS лишаються вищими приблизно на 7 п.п.; гібрид «мережа → LNS» на реальних контурах LNS не покращує; крок кута 5° замість 15° переваги не дав; повороти на 90° дають baseline 1–2 п.п. і не допомагають мережі. Донавчання з підкріпленням для кроку 5° не завершено, а мережу не донавчали на різних ширинах рулона; ширину рулона міняють лише в `width_run.js` для вихідної мережі.

### Обмеження попередніх експериментів

Пазли генеруються на ґратці 10 px з кутами, кратними 15°, що дає растровому методу структурну перевагу над Sparrow і SVGnest. Закладений розв'язок є точним оптимумом лише для пазлів без відходів. Вибірки малі, довірчих інтервалів немає; Sparrow і SVGnest запускалися по одному разу. На реальних лекалах мережа навчена на пазлах і лише переноситься, окремого навчання на реальних даних не було.

## Пазли із зонами різної форми і реальні лекала FreeSewing (листопад 2026)

- `zgen.py` — генератор: зони (півмісяці, S-подібні смуги, плями, нерівні краї; різні розміри, комбінуються) вирізаються з рулона **до** розбиття; вільна область ділиться на деталі (діаграма Вороного + викривлені краї), тож закладений розв’язок покриває її без зазорів. `python3 zgen.py <тег> <зерно> <кількість>` → `data/zgen_<тег>.json` (потрібні shapely, numpy).
- `zpuzzle.js` — перетворює запис генератора на пазл (`load`, `build`); `expert_data12.js` — дані для навчання; `train_v2.js` — навчання (`weights/v2/zA_*.json` — мережі, перенавчені на зонах: 16-8, 32-16, 32-16-8).
- `zbench.js` — порівняння на пазлах із зонами; `rl_eval.js` (+`rl_tasks.js`, види рулона `zmoon|zsshape|zmix|zragged`) — на реальних лекалах; `ext/z_sparrow_*` — Sparrow з патчем про зони.
- `ext/freesewing/` і `examples/real/fs_*.json` — реальні лекала з FreeSewing (MIT): піджак, брюки, сорочка, худі, жилет, пальто, костюм-трійка.
- `figures/build_data7.py` — дані рис. 3–4; `results/zreal_*`, `results/zpuz_*` — сирі результати.
